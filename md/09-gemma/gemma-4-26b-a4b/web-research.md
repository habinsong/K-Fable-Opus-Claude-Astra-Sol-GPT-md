## 1. 분야 규칙 — 웹 리서치

최신 정보 조사, 사실 확인, 제품·모델·규정 비교, 출처 수집 같은 웹 검색 기반 작업에 적용한다. 학술 연구는 `research`, 기술 도입 판단은 `tech-research` 문서를 함께 따른다.

### 1.1 조사 방법
- **질문부터 나눈다.** 확인할 사실을 개별 질문으로 나누고, 서로 독립적인 검색은 한꺼번에 진행한다. 검색어는 한 가지로 끝내지 않고 이름·버전·날짜를 바꿔 교차한다.
- **출처 순서를 지킨다.** 공식 문서·명세·소스 저장소·릴리즈 노트 > 공식 발표 > 신뢰할 만한 언론·논문 > 블로그·집계 사이트 > 커뮤니티. 위키·집계 사이트는 단서로만 쓰고 1차 출처에서 다시 확인한다.
- **핵심 사실은 독립된 출처 둘 이상, 또는 1차 출처 하나로 확인한다.** 서로 베낀 글은 하나로 센다. 수치·날짜·버전·가격은 원문에서 직접 대조한다.
- **읽은 범위를 구분해서 적는다.** 본문을 직접 읽은 것 / 검색 스니펫만 본 것 / 열지 못한 것을 구분한다. 페이지 요약 도구는 요약본을 돌려주므로 중요한 수치는 원문으로 다시 확인한다.
- **벤더의 주장과 독립 검증을 구분한다.** 자체 벤치마크와 마케팅 수치는 주장으로 적고, "최초·최고" 표현도 주장으로 적는다. 비교 조건(하네스·설정·날짜)이 다르면 같은 선상에 놓지 않는다.
- **날짜를 붙인다.** "확인 날짜 YYYY-MM-DD"를 쓰고, 날짜가 없는 페이지는 신뢰도를 낮춘다. 출시 예정·루머는 확정 사실과 섞지 않는다.
- **충돌하면 둘 다 적는다.** 어느 쪽을 더 신뢰하는지와 이유를 쓰고, 해소하지 못했으면 해소하지 못했다고 쓴다.
- **인용 구절은 원문에서 직접 찾는다.** 인용한 구절이 원문에 있는지 문자열로 확인하고, 모델의 "전부 읽었다"는 보고를 근거로 쓰지 않는다.

### 1.2 수집·이용의 한계
- 로봇 배제 표준(RFC 9309의 `robots.txt`), 이용 약관, 속도 제한을 지킨다. 로그인·유료벽·차단을 우회하지 않는다. 열리지 않는 사이트는 "열람 불가"로 보고하고, 사용자에게 필요한 허용 조치를 알린다.
- 개인정보는 필요한 만큼만 다루고 수집·재배포하지 않는다. 특정 개인을 조사 대상으로 삼는 요청은 목적을 확인한다.
- 본문을 길게 복사하지 않는다. 짧은 인용에 출처를 붙이고, 나머지는 자기 말로 요약한다. 이미지·데이터는 이용 조건을 확인한다.
- 모든 출처에 URL과 확인일을 남기고, 있으면 버전도 남긴다. 존재하지 않는 출처·인용·DOI를 만들지 않는다.

### 1.3 시점에 민감한 사실
아래 표는 확정된 사실이 아니라 작업 전에 공식 출처로 다시 확인할 출발점이다. 근거로 인용할 때는 직접 확인한 출처와 날짜를 함께 쓰고, 출처마다 다르다고 적힌 항목은 한쪽으로 단정하지 않는다.

| 항목 | 내용 |
|---|---|
| AI 크롤러 선호 표기 | IETF AI Preferences(어휘·robots.txt 부착) 초안은 아직 표준이 아니며 배포 사례가 없다고 보고됨. IAB 워크숍 보고서(RFC 9969)는 AI 크롤러의 robots.txt 처리가 제각각이라고 지적 |
| 논문 인용의 책임 | arXiv는 2026-05 검증 없는 LLM 출력(환각 참고문헌 등)의 명백한 증거가 있으면 1년 제출 금지를 적용한다고 발표. 저자가 내용 전체에 책임짐 |
| 검색 도구의 한계 | 이 환경의 검색은 일부 지역·도메인 결과가 빠질 수 있고, 일부 사이트는 네트워크 정책으로 열리지 않을 수 있음 |

### 1.4 보고 형식
결론 → 근거(출처 URL·확인일·확인 수준) → 충돌·불확실한 점 → 아직 모르는 것. 결론 문장은 근거 수준을 넘어서 쓰지 않는다.

### 1.5 검증 (작은 것부터)
1. 인용한 URL이 실제로 열리고 주장과 맞는지 → 2. 수치·날짜를 원문과 대조 → 3. 핵심 주장마다 출처 수 확인 → 4. 반대 근거를 일부러 한 번 검색 → 5. 결론의 확인 날짜와 한계 문장 확인.

### 1.6 하지 않는다
- 검색하지 않고 기억으로 최신 정보를 단정하지 않는다. 스니펫만 보고 본문을 읽은 것처럼 쓰지 않는다.
- 루머·예측 시장·광고성 글을 확정 사실로 쓰지 않는다.
- 차단·인증·유료 장벽을 우회하는 방법을 쓰지 않는다.

## 2. 이 모델에서 지킬 점 — 웹 리서치
- **검색은 파이프라인이 맡고, 이 모델은 읽고 정리한다.** 로컬에서 도는 모델에는 검색 grounding이 기본으로 붙지 않는다. 검색 호출과 출처 신뢰도 판단은 하네스와 사람이 하고, 모델에는 확보한 페이지 텍스트에서 제목·날짜·가격·버전 같은 필드를 JSON으로 추출하게 한다. "원문에 없으면 null"을 명시하고 값마다 근거 구절을 받아 코드로 원문 포함 여부를 대조한다.
- **판단과 종합을 맡기지 않는다.** 한 커뮤니티 평가는 이 모델이 코딩 외의 의사결정 과제에서도 고전했다고 했다. 개인 후기다. 출처 신뢰도 판정, 충돌하는 자료의 조정, 결론 작성은 상위 모델이나 사람이 맡는다(`gemini-4-argon`, `02-claude/opus-5.5`, `gpt-6.1-sol` 문서).
- **사실 회상에 기대지 않는다.** 활성 파라미터가 적은 MoE라 세부 사실 회상이 약할 수 있다는 구조상의 우려는 추정이다. 이름·날짜·수치·버전은 직접 연 출처로 확인한다.
- **긴 입력은 발췌한다.** 컨텍스트가 256K라도 큰 입력과 큰 출력이 필요한 작업에서 성능이 급락한다는 평가가 이 모델에 있다. 페이지 하나씩, 필요한 구간만 넣고 출력 필드를 짧게 제한한다. 실효 길이는 자체 입력으로 측정한다. 여러 페이지를 한 번에 넣어 "종합해 달라"고 시키지 않는다.
- **도구 호출을 쓸 때.** 사용 중인 런타임 버전에서 도구 호출 파서와 스트리밍이 정상인지 작은 시험으로 확인한다. 출시 직후 Gemma 4 계열에서 파서 오류와 스트리밍 시 도구 호출이 추론 출력으로 새는 문제가 보고됐다.
