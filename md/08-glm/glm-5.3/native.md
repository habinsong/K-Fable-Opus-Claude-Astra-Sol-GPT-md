# GLM-5.3 · 네이티브

<!-- BEGIN:domain -->
## 1. 분야 규칙 — 네이티브 프로그램

Windows·macOS·Linux 데스크톱 프로그램, CLI, 데몬, 드라이버, 라이브러리, 게임 엔진 같은 컴파일되는 시스템 소프트웨어에 적용한다.

### 1.1 구현 규칙
- **메모리 안전을 기본으로 한다.** 새 구성요소는 메모리 안전 언어(Rust, Go, Swift, C# 등)를 우선 검토한다. C·C++를 쓸 때는 소유권을 명시하고(스마트 포인터, RAII), 범위 검사 컨테이너를 쓰며, 미정의 동작(정수 오버플로, 해제 후 사용, 데이터 레이스)을 코드 리뷰 항목으로 삼는다.
- **sanitizer와 경고를 켠다.** 디버그·CI 빌드에 ASan·UBSan(스레드 코드는 TSan)과 `-Wall -Wextra` 수준의 경고를 켜고, 경고를 끄는 대신 원인을 고친다. 파서·역직렬화·프로토콜 코드는 퍼징 대상으로 본다.
- **하드닝 옵션을 유지한다.** 스택 보호, `FORTIFY_SOURCE`, PIE·RELRO, CFI 같은 플랫폼 옵션을 임의로 끄지 않는다. 끄려면 이유와 성능 측정값을 근거로 남긴다.
- **ABI·공개 헤더는 계약이다.** 구조체 레이아웃, 심볼, 에러 코드, 설정 파일 형식을 바꾸기 전에 호출자와 저장된 데이터의 호환성을 확인한다.
- **동시성은 소유자를 정한다.** 어떤 스레드가 무엇을 소유하는지와 잠금 순서를 정하고, 취소·종료 경로도 코드에 드러낸다. 전역 가변 상태를 새로 만들지 않는다.
- **플랫폼 차이를 숨기지 않는다.** 경로 구분자, 대소문자, 줄 끝, 인코딩(UTF-8/UTF-16), 권한 모델, 파일 잠금 차이를 각 OS에서 확인한다. 한 OS에서만 돌려 봤으면 그렇게 보고한다.
- **권한과 설치.** 관리자 권한은 필요한 순간에만 쓰고, 설치·업데이트 경로는 서명·검증을 거친다. 로그에 개인정보·경로 속 사용자명·토큰을 남기지 않는다.
- **패키징.** 서명(Windows 코드 서명, macOS 서명·공증), 설치·제거 절차, 크래시 리포트 수집 범위(동의 필요)를 릴리즈 전에 점검한다.
- **암호.** 직접 구현하지 않고 검증된 라이브러리를 쓴다. 장기 보관 데이터의 서명·키 교환은 전환 일정(아래 표)을 고려한다.

### 1.2 시점에 민감한 사실
아래 표는 확정된 사실이 아니라 작업 전에 공식 출처로 다시 확인할 출발점이다. 근거로 인용할 때는 직접 확인한 출처와 날짜를 함께 쓰고, 출처마다 다르다고 적힌 항목은 한쪽으로 단정하지 않는다.

| 항목 | 내용 |
|---|---|
| 메모리 안전 권고 | CISA 지침(Product Security Bad Practices v2, 2025-01)은 메모리 안전 로드맵 공개를 2025년 말까지 요구하고 신규 제품군은 메모리 안전 언어를 권장. 2030 이전 지원 종료 제품은 제외 |
| Secure Boot 인증서 | Microsoft의 2011년 발급 KEK·UEFI CA는 2026-06 말, Windows Production PCA 2011은 2026-10-19 만료(날짜는 출처마다 하루 안팎 차이). 2023 인증서로 교체 필요, PK는 OEM 소유라 영향 없음 |
| 양자내성 암호 | NIST IR 8547 최종판 기준 RSA·ECC 등은 2030 이후 deprecated, 2035 전 폐지 취지. FIPS 203(ML-KEM)·204(ML-DSA)·205(SLH-DSA)는 2024-08 발행, FIPS 206(FN-DSA)은 초안 단계로 보도됨 |

### 1.3 검증 (작은 것부터)
1. 컴파일(경고 포함) → 2. 변경한 모듈의 단위 테스트 → 3. sanitizer 빌드로 해당 테스트 → 4. 영향받는 경로의 통합·수동 실행 → 5. 대상 OS별 실행 → 6. 릴리즈 구성(최적화·서명·패키지) 마지막.
sanitizer나 다른 OS를 돌리지 못했으면 "미실행"으로 보고한다. 성능 주장은 측정값(명령·입력·환경)과 함께 쓴다.

### 1.4 하지 않는다
- 시스템 경로, 레지스트리, 부트 설정, 드라이버·커널 모듈을 승인 없이 수정·설치하지 않는다. 테스트는 격리된 디렉터리·VM·컨테이너에서 한다.
- 경고·sanitizer 보고를 억제하는 지시문을 근거 없이 추가하지 않는다.
- 서명 키·인증서·개인 키는 읽거나 출력하거나 커밋하지 않는다.
- 라이선스를 확인하지 않은 소스·바이너리·라이브러리를 번들하지 않는다(GPL 계열은 링크 방식과 배포 형태를 확인).

## 2. 이 모델에서 지킬 점 — 네이티브
- **긴 터미널 작업에 쓰려면 하네스 안전장치를 먼저 둔다.** 긴 작업에는 GLM, 검토와 어려운 변경에는 Claude라는 분업 조언이 있다(현장 시험이 아닌 권고). 에이전트 루프에는 파괴적 명령 차단(권한·훅), 작업 디렉터리 격리, 시간·토큰 한도를 두고 완료 보고는 빌드·테스트·sanitizer 출력과 `git diff`로 확인한다. 테스트·경고·sanitizer 설정이 바뀌었는지도 확인한다.
- **추론 토큰이 출력 한도에 들어간다.** 긴 추론 뒤 코드가 잘리지 않도록 `max_tokens`를 넉넉히 잡고 응답이 중간에 끊겼는지 `stop_reason`을 확인한다.
- **사실 회상을 가정하지 않는다.** 시스템 API 시그니처, 플랫폼별 동작, 표준 라이브러리 세부는 공식 문서와 컴파일러로 확인한다.
- **미공개 소스를 API로 보내기 전에 약관을 확인한다.**
- **모델은 서버 API로 호출한다.** 가중치가 수백 GB라 데스크톱 프로그램에 번들할 수 없다. 클라이언트에 API 키를 두지 않고 자체 백엔드를 거친다. 모델 출력으로 만든 경로·명령·코드를 그대로 실행하지 않으며 파서·역직렬화 코드는 퍼징 대상으로 본다.
- **오프라인 요구가 있으면 이 모델은 맞지 않는다.** 소형 로컬 모델 문서(`gemma-4-e4b`, `qwen3.6-27b` 등)를 본다. 자체 호스팅하려면 라이선스(자체 라이선스, 대규모 사업자 조항)를 원문으로 확인한다.
- **시간·토큰 상한을 둔다.** 같은 급에서 가장 느린 편이고 출력이 매우 길다.
- **공개 가중치지만 상업 이용에 제한이 있다.**
- **제3자 추론 서비스에서 요청 간 KV 캐시 노출 사고가 보고됐다.** 미공개 코드와 비밀을 호스팅 서비스에 보내기 전에 사고 공지와 격리 방식을 확인한다.
